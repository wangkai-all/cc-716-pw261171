# 代表点挑选（多维工况记录）

从少量虚构设备的多维工况记录中选出 k 个代表点，目标：**让任何未选记录离最近代表点都尽量近**（k-center，最小化最坏覆盖半径）。纯静态页面，无构建步骤。

## 运行

```bash
npm run serve          # python3 -m http.server 8000
# 打开 http://localhost:8000
```

## 测试

```bash
npm test               # 核心算法（node --test，无依赖）
npm install            # 仅 UI 测试需要 jsdom
npm run test:ui        # jsdom 端到端冒烟 + 散点图几何审计
```

## 计算流程（与页面分区一一对应）

1. **维度业务尺度**：每个维度先指定尺度，距离在「值 ÷ 尺度」归一化空间取欧氏距离。
2. **可参与样本范围**：缺失任一启用维度的记录、被排除的故障采集记录**先退出范围**——
   不允许临时忽略缺失维度后再与完整记录比距离。范围确定后才计算距离表。
3. **完整距离表**：可参与记录两两距离，页面可展开查看。
4. **代表点选择**：
   - **最远点贪心**（Gonzalez）：无约束时半径 ≤ 2 × 最优；
   - **精确枚举**：可参选记录 ≤ 18 条时枚举全部可行子集，给出受约束最优半径，用于核对贪心。
5. **分配与半径**：每条记录归属最近代表点，最坏距离即半径，被遗漏最严重的记录单独标出。

## 约束（实际进入选择过程，而非事后过滤）

- **必选样本**：直接作为初始代表点进入贪心，并作为固定成员限制枚举子集；
- **设备类型最低名额**：贪心在剩余名额等于名额缺口时强制从缺口类型选点；枚举只统计满足名额的子集；
- **排除故障采集记录**：退出参与范围（不被覆盖也不可参选）；
- **禁选某代表点**：仅取消其候选资格，记录仍被覆盖；修改后分配与半径同步重算。

> ⚠ 必选 / 名额 / 禁选任一生效时，贪心不再享有无约束情形的 2-近似保证，
> 页面会出现警告条，请以精确枚举半径核对（`src/core.js` 的 `isUnconstrained`）。

## 血缘保留

坐标相同但来源（设备 / 类型 / 批次）不同的记录**不去重**（示例数据 R15/R16）：
距离表各占一行、距离为 0，类型名额按条独立计数——不会因去重丢掉设备类型约束。

## 导出

- `representatives.csv`：两种方法选中的代表点及各自覆盖数、覆盖内最大距离；
- `assignments.csv`：每条记录的参与状态、排除原因、两种方法下的归属代表点与距离；
- `result.json`：完整配置快照（尺度 / k / 约束）+ 两种方法结果 + 全部归属。

## 文件结构

```
index.html      页面骨架
styles.css      样式（浅色主题，调色板经 CVD 校验）
src/core.js     纯函数核心：范围 / 距离表 / 贪心 / 精确枚举 / 分配 / 可行性 / CSV
src/data.js     虚构数据集（16 条记录、5 台设备、3 类类型）
src/app.js      状态与渲染：任何输入变化走同一条重算管线
test/core.test.mjs   算法测试（node --test）
scripts/ui.smoke.mjs   jsdom 端到端交互冒烟
scripts/ui.audit.mjs   散点图几何审计
```
